.. zephyr:code-sample:: mbox
   :name: MBOX
   :relevant-api: mbox_interface

   Perform inter-processor mailbox communication using the MBOX API.

Overview
********

This sample demonstrates how to use the :ref:`MBOX API <mbox_api>`.

Building and Running
********************

The sample can be built and executed on boards supporting MBOX.

Building the application for nrf5340dk/nrf5340/cpuapp
*****************************************************

.. zephyr-app-commands::
   :zephyr-app: samples/drivers/mbox/
   :board: nrf5340dk/nrf5340/cpuapp
   :goals: debug
   :west-args: --sysbuild

Open a serial terminal (minicom, putty, etc.) and connect the board with the
following settings:

- Speed: 115200
- Data: 8 bits
- Parity: None
- Stop bits: 1

Reset the board and the following message will appear on the corresponding
serial port, one is the application (APP) core another is the network (NET)
core:

.. code-block:: console

   *** Booting Zephyr OS build zephyr-v3.1.0-2383-g147aee22f273  ***
   Hello from APP
   Pong (on channel 0)
   Ping (on channel 1)
   Pong (on channel 0)
   Ping (on channel 1)
   Ping (on channel 1)
   Pong (on channel 0)
   Ping (on channel 1)
   Pong (on channel 0)
   Ping (on channel 1)
   ...


.. code-block:: console

   *** Booting Zephyr OS build zephyr-v3.1.0-2383-g147aee22f273  ***
   Hello from NET
   Ping (on channel 0)
   Pong (on channel 1)
   Ping (on channel 0)
   Pong (on channel 1)


Building the application for the simulated nrf5340bsim
******************************************************

.. zephyr-app-commands::
   :zephyr-app: samples/drivers/mbox/
   :host-os: unix
   :board: nrf5340bsim/nrf5340/cpuapp
   :goals: build
   :west-args: --sysbuild

Then you can execute your application using:

.. code-block:: console

   $ ./build/zephyr/zephyr.exe -nosim
   # Press Ctrl+C to exit

You can expect a similar output as in the real HW in the invoking console.

Building the application for kit_pse84_eval/pse846gps2dbzc4a/m33/ns
*******************************************************************

The PSOC(TM) Edge E84 does not use sysbuild for this sample. The CM55 core is
held in reset until the CM33 releases it, and that release is performed by the
secure request framework (SRF) support built into the CM33 image. The CM55
image additionally consumes the PSA manifest headers generated by the CM33
TF-M build, so the two images must be built separately and in order.

Build the CM33 (host) image first, then the CM55 (remote) image, pointing the
latter at the CM33 build directory:

.. code-block:: console

   west build -b kit_pse84_eval/pse846gps2dbzc4a/m33/ns samples/drivers/mbox \
       -d build_cm33 -- -DCONFIG_PSOC_EDGE_M55_SRF_SUPPORT=y

   west build -b kit_pse84_eval/pse846gps2dbzc4a/m55 samples/drivers/mbox/remote \
       -d build_cm55 -- -DCONFIG_PSOC_EDGE_M55_SRF_SUPPORT=y \
                        -DPSE84_CM33_BUILD_DIR=build_cm33

Flash the CM55 image first so that a valid application is present before the
CM33 tries to start that core:

.. code-block:: console

   west flash -d build_cm55
   west flash -d build_cm33

Both cores share the same console UART, so their output is interleaved on a
single terminal:

.. code-block:: console

   *** Booting Zephyr OS build ... ***
   Hello from HOST - kit_pse84_eval/pse846gps2dbzc4a/m33/ns
   Hello from REMOTE - kit_pse84_eval/pse846gps2dbzc4a/m55
   Maximum bytes of data in the TX message: 8
   Ping (on channel 0)
   Pong (on channel 0) counter 1 in 8 byte(s)
   Ping (on channel 1)
   Pong (on channel 1) counter 1 in 8 byte(s)
   ...
