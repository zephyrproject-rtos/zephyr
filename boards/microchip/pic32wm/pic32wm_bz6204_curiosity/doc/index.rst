.. zephyr:board:: pic32wm_bz6204_curiosity

Overview
********

The **PIC32-BZ6 Curiosity Board (EV31U42A)** is a versatile development platform designed to facilitate rapid prototyping and evaluation of the **PIC32WM-BZ6204UE** module.
This module supports **Bluetooth® Low Energy (BLE)** and **IEEE® 802.15.4** wireless communications.

The board is targeted at **IoT**, **Home Automation**, and **Industrial Automation** applications such as smart door locks, alarm sensors, wall switches, and thermostats.

**Key Features:**

- On-board PIC32WM-BZ6204UE wireless module (BLE and 802.15.4)
- Integrated PKOB4 programmer/debugger
- Power options: USB Type-C, External 5V, or Li-ion/Li-Po battery
- USB-UART converter for serial communication
- Two mikroBUS™ sockets for expansion
- XPRO and RMII headers for Ethernet and touch interface
- User interface: RGB LED, user LED, two push buttons, and a reset button
- Temperature sensor and external QSPI Flash memory
- External antenna connector (2.4 GHz, 2 dBi)

Hardware
********

- Integrated **USB 2.0 hub controller (USB2512B)**
- **USB Device/Host support** via Target USB Type-C connector (J103)
- **Two mikroBUS™ sockets (J903, J905)** for Click™ add-on boards
  Provide SPI, UART, I²C, PWM, Analog, Reset, Interrupt, and Power pins.
- **PTA headers (J901, J902)** for co-existence control (e.g., Wi-Fi/Bluetooth)
- **XPRO header (J900)** compatible with Microchip QT7/T9 Xplained Pro kits
- **GPIO headers (J701, J702)** to access module I/O pins
- **Graphics connector (J910)** for external GUI/Display adapter
- **RMII headers (J906–J909)** for external Ethernet PHY

Programming and Debugging
*************************

.. zephyr:board-supported-runners::

Setting Up the Debug Interface
==============================

This board can be programmed and debugged through the on-board PKOB4 debugger
connected to the **Debug USB (J100)** port. Choose the method that matches the
PKOB4 firmware mode:

- **MPLAB mode** (factory default): flash with MPLAB IPE (``west flash``) and
  flash or debug with the MPLAB extension for Visual Studio Code.
- **CMSIS-DAP mode**: flash with OpenOCD (``west flash --runner openocd``) and
  debug with the ``cortex-debug`` extension. See
  `Prerequisites: Custom OpenOCD`_.

.. note::

   The PIC32WM_BZ6 boots only signed images. Always program
   ``build/zephyr/zephyr_signed.hex``, which is generated by the build, and
   not ``zephyr.hex`` or ``zephyr.elf``.

Flash Using MPLAB IPE
=====================

For instructions on installing and configuring MPLAB IPE, see
:ref:`microchip-mplab-ipe-flashing`.

The ``mplab_ipe`` runner is the default flash runner for this board. The board's
``board.cmake`` already passes the PKOB4 tool, the part name and the signed
image to ``ipecmd``:

.. code-block:: cmake

   board_runner_args(mplab_ipe "--tool" "PKOB4" "--part" "32WM_BZ6204"
     "--hex-file=${CMAKE_BINARY_DIR}/zephyr/zephyr_signed.hex" "--erase" "--verify")

.. note::

   ``ipecmd`` adds the ``PIC`` prefix to the part name itself, so the part
   must be given as ``32WM_BZ6204`` and not ``PIC32WM_BZ6204``.

1. Make sure the PKOB4 is in MPLAB mode. If it was switched to CMSIS-DAP,
   restore it as described in `Step 1: Switch PKOB4 Firmware to CMSIS-DAP`_.

2. Add the directory containing ``ipecmd`` to your ``PATH``. For example, on
   Windows (Command Prompt):

   .. code-block:: console

      set "PATH=C:\Program Files\Microchip\MPLABX\vX.XX\mplab_platform\mplab_ipe;%PATH%"
      where ipecmd

3. Build the application:

   .. zephyr-app-commands::
      :zephyr-app: samples/basic/blinky
      :board: pic32wm_bz6204_curiosity
      :goals: build

4. Connect the board's **Debug USB (J100)** port to your host machine and close
   any other application using the PKOB4 (for example MPLAB X IDE or the MPLAB
   IPE GUI).

5. Flash the signed image:

   .. code-block:: console

      west flash

   To select the runner explicitly:

   .. code-block:: console

      west flash --runner mplab_ipe

   The log shows ``ipecmd`` being called with ``-TPPKOB4 -P32WM_BZ6204`` and
   the path to ``zephyr_signed.hex``, and ends with ``Program Succeeded``.

6. Press the **RESET** button. The user LED should start blinking.

Flash and Debug Using the MPLAB Extension for VS Code
=====================================================

For instructions on installing and configuring the MPLAB extension for Visual
Studio Code, see :ref:`microchip-mplab-vscode-debugging`. The PKOB4 must be in
MPLAB mode.

Because the device boots only signed images, flashing and debugging are done in
two steps: program ``zephyr_signed.hex`` with a program-only configuration,
then **attach** to the running target using ``zephyr.elf`` for symbols. Do not
use a ``launch`` debug configuration with ``zephyr.elf``, because it programs
the unsigned image, which the device does not boot.

1. Build the application. For more reliable stepping and breakpoints, build
   with debug optimizations:

   .. code-block:: console

      west build -p always -b pic32wm_bz6204_curiosity samples/basic/blinky -- -DCONFIG_DEBUG_OPTIMIZATIONS=y

2. Add the following configurations to ``.vscode/launch.json``:

   .. code-block:: json

      {
        "version": "0.2.0",
        "configurations": [
          {
            "name": "MPLAB Program Zephyr (signed hex) : pic32wm_bz6204_curiosity",
            "type": "mplab-core-da",
            "request": "launch",
            "program": "${workspaceFolder}/zephyr/build/zephyr/zephyr_signed.hex",
            "device": "PIC32WM_BZ6204",
            "tool": "${command:pickTool}",
            "interface": "SWD",
            "noDebug": true
          },
          {
            "name": "MPLAB Attach Zephyr : pic32wm_bz6204_curiosity",
            "type": "mplab-core-da",
            "request": "attach",
            "program": "${workspaceFolder}/zephyr/build/zephyr/zephyr.elf",
            "device": "PIC32WM_BZ6204",
            "tool": "${command:pickTool}",
            "interface": "SWD",
            "stopAtConnect": true
          }
        ]
      }

   If more than one debug tool is connected, add a ``"serial"`` field with the
   PKOB4 serial number to both configurations. Run
   ``MPLAB: List connected tools`` from the VS Code command palette to find it.

3. Program the device: open **Run and Debug** (``Ctrl+Shift+D``), select
   **MPLAB Program Zephyr (signed hex) : pic32wm_bz6204_curiosity** and press
   **F5**. Pick the PKOB4 when prompted.

4. Start debugging: select **MPLAB Attach Zephyr : pic32wm_bz6204_curiosity**
   and press **F5**. The CPU halts on connect.

5. Set breakpoints in the source, for example in ``main.c``, and press
   **Continue (F5)**. Use the debug toolbar to step, pause and inspect
   variables, the call stack and registers. To hit a breakpoint in code that
   runs only once, such as the start of ``main()``, press **Continue** and then
   press the **RESET** button on the board.

6. After changing the source, stop the debug session, rebuild, program the
   signed image again (step 3) and re-attach (step 4). The ``zephyr.elf`` used
   for debugging must come from the same build as the flashed
   ``zephyr_signed.hex``.

Prerequisites: Custom OpenOCD
=============================

.. note::

   OpenOCD support for PIC32WM_BZ6 has not yet been merged into the official
   OpenOCD release. Until the upstream PR is accepted, you must install a
   custom OpenOCD build and switch the on-board debugger firmware to CMSIS-DAP.
   This section will be removed once OpenOCD upstream support is available.

Step 1: Switch PKOB4 Firmware to CMSIS-DAP
------------------------------------------

The on-board PKOB4 debugger must be switched to CMSIS-DAP firmware before
OpenOCD can communicate with the board.

1. Install the ``pycmsisdapswitcher`` Python utility:

   .. code-block:: console

      pip install pycmsisdapswitcher

2. Download the PKOB4 switcher package from
   `openOCD-wireless pkob4-cmsis_dap-switcher
   <https://github.com/MicrochipTech/openOCD-wireless/tree/main/pkob4-cmsis_dap-switcher>`_

3. Connect the board via USB, then run:

   .. code-block:: console

      python -m pycmsisdapswitcher --action switch --target=evalboard \
        --source=<path-to-switcher>/pkob4_app_cmsis-dap.hex --fwtype=cmsis

   To revert back to MPLAB firmware:

   .. code-block:: console

      python -m pycmsisdapswitcher --action switch --target=evalboard \
        --source=<path-to-switcher>/pkob4_app.hex --fwtype=mplab

Step 2: Install Custom OpenOCD
------------------------------

1. Download the prebuilt OpenOCD binaries with PIC32WM support from
   `openOCD-wireless prebuilt binaries
   <https://github.com/MicrochipTech/openOCD-wireless/tree/main/prebuilt_binaries/windows/openocd_support_wbz_pic32wm>`_

2. Extract the ``openocd_support_wbz_pic32wm`` package to a directory of your
   choice, for example ``/opt/openocd_support_wbz_pic32wm`` on Linux/macOS or
   ``C:\openocd_support_wbz_pic32wm`` on Windows. The package contains
   prebuilt OpenOCD binaries — no source compilation is required.

3. Add the OpenOCD ``bin`` directory to your system ``PATH``:

   On Linux/macOS:

   .. code-block:: console

      export PATH=<openocd-install-dir>/bin:$PATH

   On Windows, add ``<openocd-install-dir>\bin`` to your system
   **Environment Variables → Path**.

Step 3: Workaround for Zephyr SDK v1.0.1+
-----------------------------------------

.. note::

   Zephyr SDK v1.0.1 introduced an ``openocd/host-tools`` directory containing
   its own OpenOCD executable. The build system prioritizes this SDK-provided
   OpenOCD over your custom installation, causing custom target files to be
   ignored.

   To force the build system to use your custom OpenOCD, set the following
   CMake variables. This can be done in one of two ways:

**Option A** — Add to a local ``CMakeUserPresets.json`` or a local
``boards/microchip/pic32wm/pic32wm_bz6204_curiosity/board.cmake`` override:

.. code-block:: cmake

   set(OPENOCD "<openocd-install-dir>/bin/openocd.exe"
       CACHE FILEPATH "" FORCE)
   set(OPENOCD_DEFAULT_PATH
       "<openocd-install-dir>/share/openocd/scripts"
       CACHE PATH "" FORCE)

**Option B** — Pass on the ``west build`` command line:

.. code-block:: console

   west build -p always -b pic32wm_bz6204_curiosity samples/basic/blinky \
     -DOPENOCD=<openocd-install-dir>/bin/openocd.exe \
     -DOPENOCD_DEFAULT_PATH=<openocd-install-dir>/share/openocd/scripts

Replace ``<openocd-install-dir>`` with the actual path where you extracted
the ``openocd_support_wbz_pic32wm`` package.

Flashing with OpenOCD
=====================

Follow the steps below to build and flash your application with OpenOCD. The
PKOB4 must be in CMSIS-DAP mode.

1. Open a terminal and change to the Zephyr workspace directory:

   .. code-block:: console

      cd zephyr

2. Build the application using the following command:

   .. code-block:: console

      west build -p always -b pic32wm_bz6204_curiosity .\samples\basic\blinky\

3. After a successful build, connect the PIC32WM_BZ6 device to your machine.

4. Flash the device using the ``west flash`` command. The default runner for
   this board is ``mplab_ipe``, so select the OpenOCD runner explicitly.

   If the following line is added to ``board.cmake``, OpenOCD will
   automatically use the signed image:

   .. code-block:: cmake

      board_runner_args(openocd "--hex-file=${CMAKE_BINARY_DIR}/zephyr/zephyr_signed.hex")

   .. code-block:: console

      west flash --runner openocd

   If the above line is **not** added to ``board.cmake``, pass the signed
   image explicitly on the command line:

   .. code-block:: console

      west flash --runner openocd --hex-file build/zephyr/zephyr_signed.hex

5. Ensure the flash process completes successfully. You should see confirmation messages in the terminal.

Debugging with OpenOCD
======================

To debug the PIC32WM_BZ6 application using Visual Studio Code and OpenOCD
(PKOB4 in CMSIS-DAP mode):

1. Ensure the application is built for the PIC32WM_BZ6 board.
2. Install the ``cortex-debug`` extension in Visual Studio Code.
3. Open the workspace and click the **Run and Debug** icon on the left sidebar.
4. If ``launch.json`` and ``tasks.json`` files are already present, VS Code will automatically start the debug session.
5. If prompted to create a new ``launch.json``, select the **Cortex Debug** debugger option.
6. Replace the contents of ``launch.json`` with:

   .. code-block:: json

      {
        "version": "2.0.0",
        "configurations": [
          {
            "name": "Debug PIC32WM_BZ6",
            "type": "cortex-debug",
            "request": "attach",
            "servertype": "openocd",
            "cwd": "<path to zephyr workspace>",
            "executable": "<path to zephyr project>/build/zephyr/zephyr.elf",
            "device": "PIC32WM",
            "configFiles": [
              "interface/cmsis-dap.cfg",
              "target/pic32wm.cfg"
            ],
            "gdbPath": "<path to zephyr sdk>/arm-zephyr-eabi/bin/arm-zephyr-eabi-gdb.exe",
            "preLaunchTask": "flash_pic32wm_hex",
            "postRestartCommands": [
              "symbol-file <path to zephyr project>/build/zephyr/zephyr.elf",
              "monitor reset halt",
              "break main"
            ],
            "showDevDebugOutput": "none"
          }
        ]
      }

7. Create ``tasks.json`` inside ``.vscode`` with:

   .. code-block:: json

      {
        "version": "2.0.0",
        "tasks": [
          {
            "label": "flash_pic32wm_hex",
            "type": "shell",
            "command": "openocd",
            "args": [
              "-f", "interface/cmsis-dap.cfg",
              "-f", "target/pic32wm.cfg",
              "-c", "init",
              "-c", "reset halt",
              "-c", "program <path to zephyr project>/build/zephyr/zephyr_signed.hex reset exit"
            ],
            "problemMatcher": [],
            "group": {
              "kind": "build",
              "isDefault": true
            }
          }
        ]
      }

8. Connect the PIC32WM_BZ6 Curiosity board.
9. Click the **Run and Debug** icon again and select the Debug PIC32WM_BZ6 debug option.
10. Confirm that the debugger hits the breakpoint in ``main.c``. Press **Continue** to proceed.
