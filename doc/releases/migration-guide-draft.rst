Migration guide to Zephyr v4.6.0 (Working Draft)
################################################

This document describes the changes required when migrating your application from Zephyr v4.5.0 to
Zephyr v4.6.0.

Any other changes (not directly related to migrating applications) can be found in
the :ref:`release notes<zephyr_4.6>`.

.. contents::
    :local:
    :depth: 2

Common
******

* The :file:`scripts/footprint/size_report`, :file:`scripts/footprint/compare_footprint`, and
  :file:`scripts/kconfig/diffconfig` scripts have been renamed to
  :file:`scripts/footprint/size_report.py`, :file:`scripts/footprint/compare_footprint.py`, and
  :file:`scripts/kconfig/diffconfig.py`, respectively. Users must update their invocations.

Build System
************

* :kconfig:option:`CONFIG_ROMSTART_RELOCATION_ROM`, :kconfig:option:`CONFIG_ROMSTART_REGION_ADDRESS`
  and :kconfig:option:`CONFIG_ROMSTART_REGION_SIZE` have been deprecated in
  favour of the new chosen ``zephyr,romstart`` property that should be used
  instead. While the old option created a new linker script memory region based
  on the Kconfig settings, the new behaviour uses the memory region that gets
  generated by the devicetree via the ``zephyr,memory-region`` compatible. If an
  overwrite over the board defaults is detected the Kconfig option
  :kconfig:option:`CONFIG_ROMSTART_DEPRECATED_SET` is set and old behaviour is
  preserved while indicating the deprecation. (:github:`114974`)

Kernel
******

* :c:func:`k_queue_cancel_wait` and :c:macro:`k_fifo_cancel_wait` now wake every :c:func:`k_poll`
  call waiting on the queue with ``-EINTR`` and submit every :c:func:`k_work_poll_submit` item
  waiting on it, not only the first. Code that treated a cancel as addressed to one waiter must
  re-check its own condition.

* ``z_clock_hw_cycles_per_sec`` can no longer be assigned. Timer drivers and SoC code that set the
  system timer frequency at run time must call ``z_sys_clock_hw_cycles_per_sec_set()`` instead.

Boards
******

* On the Nordic nRF54L and nRF71 Series SoCs, the push area that the Key Management Unit (KMU) of
  CRACEN uses to push keys is now reserved at the start of the SRAM by the ``kmu_push_area``
  devicetree node of the SoC. The ``zephyr,sram`` chosen node of the in-tree boards is now
  ``cpuapp_sram_app``, a child node of ``cpuapp_sram`` that starts after the push area. The nodes
  are not present when ``USE_NON_SECURE_ADDRESS_MAP`` is used. Out-of-tree boards that use the
  CRACEN KMU key push should be updated, as otherwise the application RAM overlaps the push area
  without any diagnostic. Boards that do not use it can keep using the whole RAM:

  * Replace ``zephyr,sram = &cpuapp_sram`` with ``zephyr,sram = &cpuapp_sram_app``.
  * To limit the SRAM available to the application, resize ``cpuapp_sram_app`` and keep its
    offset, for example ``reg = <0x60 (DT_SIZE_K(184) - 0x60)>``. Changing ``reg`` of
    ``cpuapp_sram`` no longer changes the SRAM that ``zephyr,sram`` refers to.
  * If the memory layout deletes and redefines ``cpuapp_sram``, assign the redefined node to
    ``zephyr,sram`` and leave the first ``0x60`` bytes of the SRAM free.
  * Remove custom nodes and linker sections that reserve the push area, such as
    ``nrf_kmu_reserved_push_area``. They would overlap the ``kmu_push_area`` node.

* On Nordic SoCs, :kconfig:option:`CONFIG_TRUSTED_EXECUTION_NONSECURE` no longer enables
  :kconfig:option:`CONFIG_BUILD_WITH_TFM` by default, as TF-M is not the only possible secure
  firmware. The in-tree ``/ns`` board targets now enable TF-M themselves. Out-of-tree non-secure
  board targets that use TF-M must do the same, in their :file:`Kconfig.defconfig`:

  .. code-block:: kconfig

     configdefault BUILD_WITH_TFM
             default y if BOARD_MY_BOARD_NRF9160_NS

* :zephyr:board:`stm32_min_dev` now declares two SoCs, so the SoC qualifier is
  mandatory. Applications and test configurations that used ``stm32_min_dev``,
  ``stm32_min_dev@blue`` or ``stm32_min_dev@black`` must use
  ``stm32_min_dev@blue/stm32f103x8`` or ``stm32_min_dev@black/stm32f103x8``
  instead. ``stm32_min_dev_defconfig`` was renamed accordingly to
  :file:`stm32_min_dev_stm32f103x8_defconfig`.

* The Adafruit ESP32 Feather board target ``adafruit_feather_esp32`` has been renamed to
  :zephyr:board:`adafruit_feather_esp32_v2` (``adafruit_feather_esp32_v2``) to match the
  manufacturer's naming: Adafruit ESP32 Feather V2. The old ``adafruit_feather_esp32``
  board target is deprecated and now automatically redirects to the new target with a warning.
  Update board targets from ``adafruit_feather_esp32/esp32/procpu`` and
  ``adafruit_feather_esp32/esp32/appcpu`` to ``adafruit_feather_esp32_v2/esp32/procpu`` and
  ``adafruit_feather_esp32_v2/esp32/appcpu`` respectively. The new board defines no revisions,
  so drop the ``@2`` revision suffix if it was specified: ``adafruit_feather_esp32@2`` is not
  redirected and fails with an invalid board revision error.

* :zephyr:board:`cy8ckit_041s_max`: the console moved from SCB2 to SCB1 on the same pins (P0.4,
  P0.5), and its node label changed from ``uart2`` to ``uart1``. The ``spi1`` node on SCB1
  (P2.0 to P2.2) was removed. SCB2 is now ``arduino_spi`` on the Arduino header pins D11 to D13
  (P10.0 to P10.2), disabled by default.

* LiteX: The deprecated ``CONFIG_LITEX_CSR_DATA_WIDTH`` Kconfig option has been removed. Only the
  32 bit CSR data width is supported. Designs that use an 8 bit CSR data width must be rebuilt with
  a 32 bit CSR data width. (:github:`124793`)

* The Andes AE350 SoC is now provided per AndesCore core, for example ``ae350_a25`` for the A25
  core. The ``ae350`` SoC and :kconfig:option:`CONFIG_SOC_AE350` are deprecated and will be
  removed in a future release. Kconfig, CMake and code checking
  :kconfig:option:`CONFIG_SOC_AE350` should check :kconfig:option:`CONFIG_SOC_SERIES_AE350`
  instead. (:github:`122288`)

  * The AE350 board targets of :zephyr:board:`adp_xc7k` and
    :zephyr:board:`tang_mega_138k_pro_dock` have been renamed after the core. The previous board
    targets are deprecated and map to the new board targets:

    * ``adp_xc7k/ae350`` to ``adp_xc7k/ae350_a25``
    * ``adp_xc7k/ae350/clic`` to ``adp_xc7k/ae350_d23/clic``
    * ``tang_mega_138k_pro_dock/ae350`` to ``tang_mega_138k_pro_dock/ae350_a25``
    * ``tang_mega_138k_pro_dock/ae350/demo`` to ``tang_mega_138k_pro_dock/ae350_a25/demo``

  * Applications must rename their board specific files after the new board targets, for
    example :file:`boards/adp_xc7k_ae350.overlay` to :file:`boards/adp_xc7k_ae350_a25.overlay`,
    as the files named after the previous board targets are no longer applied. Kconfig, CMake
    and code checking ``CONFIG_BOARD_ADP_XC7K_AE350`` must check
    ``CONFIG_BOARD_ADP_XC7K_AE350_A25`` instead.
  * Out-of-tree boards using the ``ae350`` SoC should use the ``ae350_<core>`` SoC of their core
    in ``board.yml``, rename the board files named after the SoC, select ``SOC_AE350_<core>``
    instead of ``SOC_AE350``, and include the :file:`riscv/andes/andes_v5_ae350_<core>.dtsi` of
    their core. Boards describing their own CPU nodes must use the compatible of the core, for
    example :dtcompatible:`andestech,a25`, which enables the ``CONFIG_CPU_ANDES_<core>`` option
    selecting the CPU features of the core.
  * :file:`riscv/andes/andes_v5_ae350.dtsi` now describes a single CPU instead of eight, and the
    PLIC also has the supervisor mode context of the hart. Out-of-tree boards including it must
    drop the deletes of the other CPU nodes. Multicore boards must add the other CPU nodes and
    add them to the ``interrupts-extended`` of ``plic0``, ``mtimer`` and ``plic_sw``, or include
    the :file:`riscv/andes/andes_v5_ae350_<core>mp.dtsi` of their core.

* The RAKwireless ``rak3172`` board is renamed to :zephyr:board:`rak3272s`. It
  was named after the WisDuo stamp module it carries rather than the board it
  describes, which is the RAK3272S Breakout Board. The other carrier for the
  same module is the new :zephyr:board:`rak3372` WisBlock Core Module.
  :file:`boards/deprecated.cmake` keeps ``-b rak3172`` working with a warning,
  but out-of-tree code testing ``CONFIG_BOARD_RAK3172`` must switch to
  ``CONFIG_BOARD_RAK3272S``.

* :zephyr:board:`rak3272s` no longer defines ``led0``. The RAK3272S carries no
  LEDs and leaves the two module pins the nodes used unrouted. Applications
  that relied on the alias, such as :zephyr:code-sample:`blinky`, need an
  overlay pointing at a LED wired to the headers.

* The Espressif SoC family is renamed from ``espressif_esp32`` to ``espressif``. The
  :kconfig:option:`CONFIG_SOC_FAMILY` string is now ``"espressif"`` and the family option is
  :kconfig:option:`CONFIG_SOC_FAMILY_ESPRESSIF`. ``CONFIG_SOC_FAMILY_ESPRESSIF_ESP32`` is still set
  for Espressif SoCs, but it is deprecated and will be removed in a future release. Use
  :kconfig:option:`CONFIG_SOC_FAMILY_ESPRESSIF` instead.

* The Kconfig options defined by the Espressif SoCs in :file:`soc/espressif` now use the SoC
  symbol prefixes required by the Kconfig naming conventions. Options shared by the Espressif SoC
  family use ``SOC_FAMILY_ESPRESSIF_`` and options that belong to a single SoC use ``SOC_<SoC>_``.
  The former ``ESP_``, ``ESP32_``, ``ESP32<SoC>_`` and ``SOC_ESP32_`` prefixes are dropped, and
  options that had no vendor prefix, such as ``SPIRAM_*``, ``SPI_FLASH_*`` and ``BOOTLOADER_*``,
  gain the family prefix. The flash options lose the ``ESPTOOLPY_`` tool name (``FLASHFREQ`` and
  ``FLASHMODE`` become ``FLASH_FREQ`` and ``FLASH_MODE``), and a few redundant words are dropped.
  For example:

  * ``CONFIG_ESP_SPIRAM`` is now :kconfig:option:`CONFIG_SOC_FAMILY_ESPRESSIF_SPIRAM`.
  * ``CONFIG_SPIRAM_MODE_OCT`` is now :kconfig:option:`CONFIG_SOC_FAMILY_ESPRESSIF_SPIRAM_MODE_OCT`.
  * ``CONFIG_ESPTOOLPY_FLASHFREQ_80M`` is now
    :kconfig:option:`CONFIG_SOC_FAMILY_ESPRESSIF_FLASH_FREQ_80M`.
  * ``CONFIG_ESPTOOLPY_OCT_FLASH`` is now :kconfig:option:`CONFIG_SOC_ESP32S3_FLASH_OCTAL`.
  * ``CONFIG_ESP32_ULP_COPROC_ENABLED`` is now
    :kconfig:option:`CONFIG_SOC_FAMILY_ESPRESSIF_ULP_ENABLED`.
  * ``CONFIG_ESP_CONSOLE_UART_NUM`` is now
    :kconfig:option:`CONFIG_SOC_FAMILY_ESPRESSIF_CONSOLE_UART_NUM`.
  * ``CONFIG_SOC_ESP32_PM_SUPPORT_CPU_PD`` is now
    :kconfig:option:`CONFIG_SOC_FAMILY_ESPRESSIF_PM_SUPPORT_CPU_PD`.
  * ``CONFIG_ESP32S3_DATA_CACHE_64KB`` is now :kconfig:option:`CONFIG_SOC_ESP32S3_DATA_CACHE_64KB`.
  * ``CONFIG_ESP32_CACHE_L2_512KB`` is now :kconfig:option:`CONFIG_SOC_ESP32P4_CACHE_L2_512KB`.

  The old names of the options that can be set by users are kept as deprecated options and will be
  removed in a future release. Setting one of them forwards the value to the renamed option and
  prints a deprecation warning when the value differs from the default of that option. Configuration
  files should still be updated, because the following uses of the old names are not covered:

  * Code that tests an old boolean ``CONFIG_`` macro. A deprecated boolean option only appears in
    :file:`autoconf.h` when it is set.
  * Board ``Kconfig.defconfig`` files that change the default of a renamed option or choice, for
    example ``choice SPIRAM_MODE``. They must use the new option and choice names.
  * A deprecated option set by an application does not override a value that a board sets for the
    renamed option.

  The options ``CONFIG_ESPTOOLPY_FLASHSIZE_*``, ``CONFIG_ESPTOOLPY_HEADER_FLASHSIZE_UPDATE``,
  ``CONFIG_ESPTOOLPY_BEFORE_*``, ``CONFIG_ESPTOOLPY_AFTER_*``,
  ``CONFIG_ESP32_DEEP_SLEEP_WAKEUP_DELAY``, ``CONFIG_SPIRAM_TYPE_ESPPSRAM*``,
  ``CONFIG_ESP32S3_INSTRUCTION_CACHE_WRAP``, ``CONFIG_ESP32S3_DATA_CACHE_WRAP``,
  ``CONFIG_ESP32_ULP_PANIC_OUTPUT_ENABLE`` and ``CONFIG_ESP32_ULP_RISCV_INTERRUPT_ENABLE`` have
  been removed because they had no effect. Remove them from configuration files. Board
  ``Kconfig.defconfig`` files must drop their ``choice SPIRAM_TYPE`` overrides. The flash size
  comes from the ``zephyr,flash`` devicetree node.

* On LiteX SoCs, :kconfig:option:`CONFIG_SYS_CLOCK_HW_CYCLES_PER_SEC` no longer falls back to the
  CPU ``clock-frequency`` when ``/cpus`` has no ``timebase-frequency``. Out-of-tree boards must
  set ``timebase-frequency`` on the ``/cpus`` node. (:github:`124446`)

* The NXP LPC54xxx DTSI files are named after the sub-family they describe and all live in
  :file:`dts/arm/nxp/lpc/lpc54xxx/`. Out-of-tree boards must update their includes:

  * LPC5411x: :file:`nxp/lpc/lpc54xxx/nxp_lpc54xxx.dtsi`,
    :file:`nxp/lpc/lpc54xxx/nxp_lpc54xxx_m4.dtsi` and
    :file:`nxp/lpc/lpc54xxx/nxp_lpc54xxx_m0.dtsi` are now
    :file:`nxp/lpc/lpc54xxx/nxp_lpc5411x.dtsi`,
    :file:`nxp/lpc/lpc54xxx/nxp_lpc5411x_m4.dtsi` and
    :file:`nxp/lpc/lpc54xxx/nxp_lpc5411x_m0.dtsi`.
  * LPC546xx: :file:`nxp/lpc/nxp_lpc546xx.dtsi` is now
    :file:`nxp/lpc/lpc54xxx/nxp_lpc546xx.dtsi`.

  The root compatible of the LPCXpresso54114 board is now ``nxp,lpc5411x`` instead of
  ``nxp,lpc54xxx``. (:github:`125465`)

* Antmicro ``stm32h7_renode_reference_board`` has been renamed to
  ``stm32h7_renode_reference_platform``. The previous ``-b stm32h7_renode_reference_board``
  and ``-b stm32h7_renode_reference_board/stm32h753xx`` are deprecated and now map to
  ``stm32h7_renode_reference_platform`` and ``stm32h7_renode_reference_platform/stm32h753xx``.

* On :zephyr:board:`mimxrt1180_evk`, the optional DTS overlay files
  (:file:`cm33_sram_dtcm.overlay`, :file:`cm7_code_hyperram.overlay`,
  :file:`cm7_flash_boot.overlay`) and on :zephyr:board:`frdm_imxrt1186` the
  :file:`cm33_sram_dtcm.overlay` file were moved from the board root directory into a
  dedicated :file:`dts/` subdirectory. Out-of-tree applications that referenced these
  files with an explicit path must update it to include the ``dts/`` component
  (e.g. use :zephyr_file:`boards/nxp/mimxrt1180_evk/dts/cm7_flash_boot.overlay`
  instead of :file:`boards/nxp/mimxrt1180_evk/cm7_flash_boot.overlay`).

* On the Alif Ensemble RTSS and Balletto cores, :kconfig:option:`CONFIG_NUM_IRQS` now defaults
  to the highest IRQ of the enabled devicetree nodes plus one, instead of 480. Applications that
  connect a higher IRQ with :c:macro:`IRQ_CONNECT()` or :c:func:`irq_connect_dynamic` must set
  :kconfig:option:`CONFIG_NUM_IRQS` explicitly.

ADC
===

* :dtcompatible:`nxp,lpc-lpadc` channels that use ``ADC_GAIN_1_2`` for the 30/64 partial scale
  should use ``ADC_GAIN_15_32``: with ``ADC_GAIN_1_2``, which still selects that scale, the
  conversions of :c:func:`adc_raw_to_millivolts_dt` and :c:func:`adc_raw_to_millivolts` are
  6.25% too low.

Audio Codec
===========

* The :dtcompatible:`wolfson,wm8904` binding now requires the ``clocks`` and ``clock-names``
  properties. The MCLK input must always be described in devicetree, either by a clock controller
  or by a :dtcompatible:`fixed-clock` node when it is not backed by a controllable clock source.
  The driver no longer falls back to computing MCLK as ``fs-ratio * <sample rate>``.

  The ``fs-ratio`` property has been replaced by ``fll-sysclk-fs-ratio``, which now only sets the
  SYSCLK to sample rate ratio generated by the FLL when ``clock-source`` is ``"FLL"``. It is
  ignored when ``clock-source`` is ``"MCLK"``.

  Out-of-tree boards and overlays must be updated, for example:

  .. code-block:: devicetree

     mclk: mclk {
             compatible = "fixed-clock";
             clock-frequency = <12288000>;
             #clock-cells = <0>;
     };

     &wm8904 {
             clocks = <&mclk>;
             clock-names = "mclk";
     };

  When using a :dtcompatible:`fixed-clock` node,
  :kconfig:option:`CONFIG_CLOCK_CONTROL_FIXED_RATE_CLOCK` must be enabled.

Clock control
=============

* NXP MCXC and K32L2B3 SoCs now use the :dtcompatible:`nxp,mcg-lite` binding and driver
  for the MCG-Lite clock generator. Out-of-tree devicetrees must update the mcg node to use
  the new compatible and replace any use of ``KINETIS_MCG_OUT_CLK`` with
  ``NXP_MCG_LITE_OUT_CLK``. The ``lircdiv2`` property is no longer supported by
  :dtcompatible:`nxp,kinetis-mcg` and should be removed from existing devicetrees.

Comparator
==========

* The deprecated ``mcux_lpcmp`` sensor driver, its public header
  ``zephyr/drivers/sensor/mcux_lpcmp.h``, the ``CONFIG_MCUX_LPCMP_TRIGGER`` option and its sample
  have been removed. Applications using ``CONFIG_MCUX_LPCMP`` must enable
  :kconfig:option:`CONFIG_COMPARATOR` and
  :kconfig:option:`CONFIG_COMPARATOR_NXP_LPCMP` and migrate to the :ref:`comparator_api` instead of
  the sensor API.

  The :dtcompatible:`nxp,lpcmp` devicetree compatible is unchanged, but existing overlays must be
  updated for the comparator driver. Legacy sensor properties remain in the binding but are not
  consumed by the comparator driver:

  * Replace ``hysteresis-level`` with ``hysteresis-mode``, converting integer values ``0`` through
    ``3`` to strings ``"LEVEL0"`` through ``"LEVEL3"``.
  * ``power-level = "low"`` becomes ``power-mode = "low_speed"`` and
    ``power-level = "high"`` becomes ``power-mode = "high_speed"``. The old ``"nano"`` value has
    no corresponding ``power-mode`` setting.
  * Replace ``enable-output-pin`` with ``enable-pin-out``. Use ``invert-output`` for output
    inversion.
  * The ``function-clock`` property is not used by the comparator driver. Review the SoC clock
    configuration and the standard ``clocks`` property separately; ``clocks`` is not a direct
    replacement for the LPCMP internal functional clock-source selection.

  Refer to :zephyr_file:`dts/bindings/comparator/nxp,lpcmp.yaml` for the property definitions. The
  :zephyr_file:`tests/drivers/comparator/gpio_loopback` test provides an example of the comparator
  API. (:github:`124232`).

Ethernet
========

* :kconfig:option:`CONFIG_ETH_PHY_DRIVER` is no longer enabled by default. It is now selected by
  the Ethernet drivers that need a PHY driver. Out-of-tree Ethernet drivers that use a PHY driver
  must select it as well. (:github:`120871`)

* The Kconfig option ``CONFIG_ETH_INTEL_IGC_NET_MTU`` has been removed. The Intel IGC Ethernet
  driver now always uses the standard Ethernet MTU of 1500 bytes, as the Ethernet L2 does not
  support jumbo frames. (:github:`122863`)

* The ``reset-gpios`` timing properties of the Ethernet PHY bindings, such as
  :dtcompatible:`ethernet-phy` and :dtcompatible:`ethernet-phy-fixed-link`, have been renamed to
  align with the Linux Ethernet PHY binding, which uses the same names.
  Replace ``reset-assert-duration-us`` with ``reset-assert-us``, and replace
  ``reset-deassertion-timeout-ms`` with ``reset-deassert-us``, multiplying its value by 1000 as
  it is now in microseconds. (:github:`124061`)

* The ``ETHERNET_LLDP`` value of :c:enum:`ethernet_hw_caps` has been removed. LLDP is now enabled
  on every Ethernet interface when :kconfig:option:`CONFIG_NET_LLDP` is set. Out-of-tree Ethernet
  drivers must stop reporting it. (:github:`124787`)

* The ``ETHERNET_DSA_USER_PORT`` and ``ETHERNET_DSA_CONDUIT_PORT`` values of
  :c:enum:`ethernet_hw_caps` have been removed. Use :c:func:`net_eth_get_dsa_port_type` to get the
  DSA port type of an interface instead. (:github:`124790`)

Flash
=====

* The Espressif flash encryption compatibility option ``CONFIG_ESP_FLASH_ENCRYPTION`` is now
  :kconfig:option:`CONFIG_ESP32_FLASH_ENCRYPTION`, defined by the ESP32 flash driver. The old name
  is kept as a deprecated option and will be removed in a future release.

I2S
===

* :kconfig:option:`CONFIG_I2S_NATIVE_SIM_RX_FILE_PATH` and
  :kconfig:option:`CONFIG_I2S_NATIVE_SIM_TX_FILE_PATH` are deprecated. Use
  :kconfig:option:`CONFIG_I2S_NATIVE_SIM_RX_PATH` and
  :kconfig:option:`CONFIG_I2S_NATIVE_SIM_TX_PATH`, which also accept ALSA devices. Without the
  ALSA backend the old options still provide their default. (:github:`123474`)

Interrupt Controllers
=====================

* GIC v3 LPI and ITS tables now use static storage instead of the system heap.
  Applications must provision enough table capacity for their devices and interrupt vectors.
  (:github:`120728`)

  Enabling :kconfig:option:`CONFIG_GIC_V3_ITS` requires :kconfig:option:`CONFIG_NUM_IRQS` to be
  greater than 8192 because LPI INTIDs start at 8192. Set :kconfig:option:`CONFIG_NUM_IRQS` to at
  least 8192 plus the total number of required LPIs across all ITS instances. Hardware support
  and ``zephyr,lpi-id-bits`` can further limit the usable LPI range.

  Set :kconfig:option:`CONFIG_GIC_V3_ITS_MAX_DEVICES` to at least the number of distinct DeviceIDs
  registered with each ITS instance; the default is 16. Set
  :kconfig:option:`CONFIG_GIC_V3_ITS_MAX_VECTORS` to at least the largest number of vectors
  requested for any one device. Use a power of two from 2 to 2048. The default is 32.
  Increasing these capacities can increase the statically reserved memory, including space for
  devices that are not registered.

  The ``zephyr,device-id-bits`` property of :dtcompatible:`arm,gic-v3-its` must cover the largest
  DeviceID used by the platform, rather than the number of devices. Its default of 16 covers the
  PCIe RequesterID space. The ``zephyr,lpi-id-bits`` property of :dtcompatible:`arm,gic-v3` controls
  the LPI table provision and defaults to 16; reduce it only when all required INTIDs fit in the
  smaller range.

  Platforms with known ITS table geometry can use ``zephyr,device-table-size`` to cap the Device
  table reservation in bytes. The driver reserves the smaller of this cap and the automatically
  calculated size. The reservation must fit the direct table or, in indirect mode, the root and
  enough second-level pages for the configured device capacity. If all supported layouts exceed
  the reservation or the BASER page limit, ITS initialization fails with ``-ENOSPC`` before
  enabling the tables.

  Remove application or board :kconfig:option:`CONFIG_HEAP_MEM_POOL_SIZE` overrides that only
  reserved space for GIC v3 LPI or ITS tables. The ITS no longer contributes a minimum heap size.
  Retain any heap space needed by other drivers or application allocations.

  :c:func:`its_alloc_intid` is deprecated. Its signature and the
  :c:type:`its_api_alloc_intid_t` driver callback remain unchanged during deprecation.
  The GICv3 ITS driver now returns ``0`` from this function when it cannot allocate an LPI INTID.
  Callers that still use it must check for ``0`` before using the returned INTID.
  Use :c:func:`its_alloc_intids` with a count of 1 to allocate a single INTID:

  .. code-block:: c

     unsigned int intid;
     int ret = its_alloc_intids(dev, 1U, &intid);

     if (ret != 0) {
             /* ret is -ENOSPC or another negative error code. */
     }

  The new :c:func:`its_alloc_intids` and :c:func:`its_alloc_map_intids` functions return 0 on
  success, a negative error code on failure, and store the first allocated INTID through the
  output parameter. The output parameter is left unchanged on failure. ITS driver implementations
  retain the ``alloc_intid`` callback and implement the new ``alloc_intids`` and ``alloc_map_intids``
  callbacks for the replacement APIs.

  Map each EventID only once per DeviceID. :c:func:`its_map_intid` returns ``-EBUSY`` for
  an existing mapping. Use :c:func:`its_send_int` only after mapping the EventID successfully.

  A failed mapping request leaves its output parameter unchanged. If hardware rollback cannot
  be confirmed, potentially mapped INTIDs and EventIDs remain reserved. These INTIDs reduce
  the capacity available to later requests, and retrying the same EventIDs returns ``-EBUSY``.
  Published indirect Device table pages also remain reserved after failed device setup.

MFD
===

* nPM13xx event callbacks now use :c:struct:`mfd_npm13xx_event_callback` instead of
  :c:struct:`gpio_callback`. Set its ``handler`` and ``event_mask`` fields directly instead of
  calling ``gpio_init_callback()``. The handler takes a pointer to the new callback structure
  and an ``npm13xx_event_t`` event mask; existing ``BIT(NPM13XX_EVENT_*)`` masks are unchanged.
  (:github:`123060`)

Modem
=====

* Sierra Wireless HL78xx: the ``CONFIG_HL78XX_EVT_MONITOR_HEAP_SIZE`` option has been replaced
  by :kconfig:option:`CONFIG_HL78XX_EVT_MONITOR_QUEUE_DEPTH`. The queue of notifications
  waiting for the deferred event monitors is now sized as a number of notifications instead of
  a heap size in bytes. Applications that set the old option must remove it, and set the new
  one if the default of 16 notifications is not enough. A notification that does not fit is
  dropped and counted; the count is available from
  :c:func:`hl78xx_evt_monitor_dropped_count`. The slots are reserved statically, one queued
  notification each, so the default of 16 uses more RAM than the 256-byte heap it replaces.
  (:github:`120425`)

OPAMP
=====

* The NXP OPAMP drivers (:dtcompatible:`nxp,opamp` and :dtcompatible:`nxp,opamp-fast`) hold a
  power state constraint while the device is active, and the OPAMP nodes declare
  ``zephyr,disabling-power-states``. With :kconfig:option:`CONFIG_PM_POLICY_DEVICE_CONSTRAINTS`
  an enabled OPAMP therefore keeps the system out of Power Down and Deep Power Down for as long
  as it is active, which without :kconfig:option:`CONFIG_PM_DEVICE_RUNTIME` is from init onwards.
  Enable device runtime PM for the node, or suspend it explicitly, to let the system reach those
  states. (:github:`122135`)

* :dtcompatible:`nxp,opamp-fast` no longer enables an instance marked with
  ``is-reference-source`` from its init function; the instance follows its own power state like
  every other instance. With :kconfig:option:`CONFIG_PM_DEVICE_RUNTIME` an application has to hold
  a runtime reference on the reference source while it measures an amplifier fed by it. Builds
  without device runtime PM are unaffected: the device is resumed at init and the instance comes
  up enabled as before. (:github:`122135`)

PCIe
====

* :c:func:`pcie_msi_map` now returns ``uint64_t`` instead of ``uint32_t``, and the ``address``
  member of :c:struct:`msi_vector_generic` is now ``uint64_t``. Out-of-tree implementations of
  :c:func:`pcie_msi_map` and code that reads the MSI vector address must be updated. The ITS
  getter (:c:func:`its_get_msi_addr`) also returns ``uint64_t``. (:github:`124156`)

* A 32-bit MSI capability whose ITS target address is above 4 GiB now makes
  :c:func:`pcie_msi_enable` return false without writing the configuration space or enabling bus
  mastering; dependent drivers such as NVMe, ivshmem and IGC fail to initialize. This is
  intentional: use a 64-bit MSI capability or a target address below 4 GiB. (:github:`124156`)

Power Management
================

* NXP MCX :dtcompatible:`nxp,spc` ``wakeup-delay`` specifies regulator-settling delay in
  SPC timer cycles. At the nominal 10 MHz timer frequency, every additional 100 cycles
  adds approximately 10 us to wake-up time. A nonzero programmed delay can also apply
  when ``LP_CFG`` and ``ACTIVE_CFG`` select the same voltage.
  SoC power-state ``exit-latency-us`` defaults include SPC settling and mode-specific
  recovery allowances. Board/application overlays can select counts for their regulator,
  voltages, output capacitance and external power circuitry. Measure the total wake-up
  time for the actual project, including clock recovery and resume processing, and adjust
  ``exit-latency-us`` accordingly; these defaults are not measured worst-case bounds.

PTP Clock
=========

* :c:func:`ptp_clock_rate_adjust` and the :c:member:`ptp_clock_driver_api.rate_adjust` driver
  operation, which take the clock rate as a floating-point ratio, have been deprecated. Use
  :c:func:`ptp_clock_adjust_rate` and implement :c:member:`ptp_clock_driver_api.adjust_rate`
  instead, which take the rate offset from the nominal frequency as scaled parts per million,
  that is parts per million with a 16-bit binary fractional field:
  ``scaled_ppm = (ratio - 1) * 1000000 * 65536``. :c:macro:`PTP_CLOCK_SCALED_PPM_ONE` is 1 ppm.

  A driver only has to implement one of the two operations. Both functions work with either of
  them and convert the argument if necessary, so applications and drivers can be migrated
  independently.

  Drivers can use :c:func:`ptp_clock_scaled_ppm_to_ppb` if the hardware takes the offset in
  parts per billion, and :c:func:`ptp_clock_adjust_by_scaled_ppm` to compute the value of an
  addend register from its nominal value. All in-tree drivers have been converted.
  (:github:`120828`)

Serial
======

* The ``CONFIG_UART_ESP32_RX_FIFO_THRESH`` and ``CONFIG_UART_ESP32_TX_FIFO_THRESH`` Kconfig options
  of the Espressif UART driver are deprecated. Set the ``rx-fifo-threshold`` and
  ``tx-fifo-threshold`` properties of each UART node in devicetree instead. The Kconfig options
  applied to every UART instance, while the properties apply to the node that sets them.
  (:github:`119492`)

* The ``CONFIG_UART_XLNX_PS`` Kconfig option has been removed in favour of
  :kconfig:option:`CONFIG_UART_CDNS`. Nodes with :dtcompatible:`xlnx,xuartps` must add
  :dtcompatible:`cdns,uart`; the :dtcompatible:`xlnx,xuartps` compatible remains valid as a hardware
  identifier, the unified driver matches on :dtcompatible:`cdns,uart`. The ``bdiv`` property has been
  removed; the baud rate is now computed from ``clock-frequency`` and ``current-speed``.
  (:github:`114729`)

Timers
======

* The deprecated Cortex-M SysTick low-power companion Kconfig options have been removed.
  Replace them with their generic system timer equivalents:

       - Replacement
     * - ``CONFIG_CORTEX_M_SYSTICK_LPM_TIMER_NONE``
       - :kconfig:option:`CONFIG_SYSTEM_TIMER_LPM_COMPANION_NONE`

     * - ``CONFIG_CORTEX_M_SYSTICK_LPM_TIMER_HOOKS``

     * - ``CONFIG_CORTEX_M_SYSTICK_RESET_BY_LPM``
       - :kconfig:option:`CONFIG_SYSTEM_TIMER_RESET_BY_LPM`

* The deprecated chosen ``/chosen/zephyr,cortex-m-idle-timer`` is no longer supported. Use the

* The ``CONFIG_MCUX_OS_TIMER_MIN_DELAY`` Kconfig option has been removed. The NXP OS Timer driver
  now uses the generic system timer core, which keeps the match value at least 16 timer cycles
  ahead of the counter. Remove the option from application and board configurations.

W1
==

* The 1-Wire API now uses controller/peripheral terminology. The former names remain available as
  deprecated aliases:

  * :c:struct:`w1_master_config` is deprecated in favor of :c:struct:`w1_controller_config`, and
    its ``slave_count`` member is deprecated in favor of ``peripheral_count``.
  * :c:struct:`w1_master_data` is deprecated in favor of :c:struct:`w1_controller_data`.
  * :c:struct:`w1_slave_config` is deprecated in favor of :c:struct:`w1_peripheral_config`.
  * :c:func:`w1_get_slave_count` is deprecated in favor of :c:func:`w1_get_peripheral_count`.
  * ``W1_SLAVE_COUNT`` and ``W1_INST_SLAVE_COUNT`` are deprecated in favor of
    ``W1_PERIPHERAL_COUNT`` and ``W1_INST_PERIPHERAL_COUNT``.

* The common devicetree binding include files ``w1-master.yaml`` and ``w1-slave.yaml`` are
  deprecated in favor of ``w1-controller.yaml`` and ``w1-peripheral.yaml``. Out-of-tree bindings
  should update their ``include:`` statements accordingly; the old files are kept as thin
  includes of the new ones for compatibility.

Wi-Fi
=====

* :kconfig:option:`CONFIG_ESP32_WIFI_STA_RECONNECT` now only applies to an Espressif station
  that loses an established connection. It reconnects with a growing backoff until it succeeds
  or the application disconnects. While it reconnects, connection requests fail with
  ``-EALREADY``. The option no longer changes how connection requests made by the application
  are handled.

* :kconfig:option:`CONFIG_ESP32_WIFI_STA_RECONNECT` is now enabled by default, so an Espressif
  station that loses an established connection reconnects on its own. Set the option to ``n`` to
  keep the station disconnected instead.

* Espressif Wi-Fi connection requests now retry authentication and association failures, such as
  an access point that rejects the first attempt after the station was reset, instead of failing
  on the first rejection. A request that leaves the ``timeout`` field of
  :c:struct:`wifi_connect_req_params` at 0 fails after three short retries. A request with a
  timeout retries until it expires and then reports a connection timeout, and one with
  ``SYS_FOREVER_MS`` retries until the application disconnects. A wrong WPA3-SAE password cannot
  be told apart from such a rejection, so it is retried as well.

Bluetooth Classic
=================

* The L2CAP BR/EDR ECHO API is now only available with :kconfig:option:`CONFIG_BT_TESTING`:
  :c:struct:`bt_l2cap_br_echo_cb`, :c:func:`bt_l2cap_br_echo_cb_register`,
  :c:func:`bt_l2cap_br_echo_cb_unregister`, :c:func:`bt_l2cap_br_echo_req` and
  :c:func:`bt_l2cap_br_echo_rsp`. The stack answers a received ECHO request with an ECHO response
  without data, unless a registered ``req`` callback handles it.

Bluetooth HCI
=============

* The STM32WB HCI driver now constructs its generated public Bluetooth address using the low
  16 bits of the device UDN, the device ID, and the full 24-bit ST company ID. This corrects the
  previous address layout and changes the generated address on affected devices. Previously bonded
  peers may need to remove the old bond and pair with the device again.

Bluetooth Host
==============

* The ATT prepare write buffers (:kconfig:option:`CONFIG_BT_ATT_PREPARE_COUNT`) are now shared
  equally between connections: a single connection holds at most
  :kconfig:option:`CONFIG_BT_ATT_PREPARE_COUNT_PER_CONN` of them, which defaults to
  ``CONFIG_BT_ATT_PREPARE_COUNT / CONFIG_BT_MAX_CONN`` but at least 1 (a pool smaller than
  ``CONFIG_BT_MAX_CONN`` therefore stays over-subscribed), and its further Prepare Write
  Requests are rejected with Prepare Queue Full. Applications with ``CONFIG_BT_MAX_CONN``
  above 1 whose long or reliable writes need more buffers than that share must either raise
  ``CONFIG_BT_ATT_PREPARE_COUNT`` or set ``CONFIG_BT_ATT_PREPARE_COUNT_PER_CONN`` explicitly,
  accepting in the latter case that one connection can hold buffers the others need. The
  recommended sizing is ``CONFIG_BT_ATT_PREPARE_COUNT`` = buffers needed by one client
  multiplied by ``CONFIG_BT_MAX_CONN``, which keeps every connection's capacity independent
  of the other connections.
* ``CONFIG_BT_ISO_TX_MTU`` has been removed. Applications should define their own SDU buffer sizes.
  The ISO HCI data buffer size can be configured for the Controller with
  :kconfig:option:`CONFIG_BT_CTLR_ISO_TX_BUFFER_SIZE`, and the SDU size with
  :kconfig:option:`CONFIG_BT_CTLR_ISO_TX_SDU_LEN_MAX`.
  In most cases :kconfig:option:`CONFIG_BT_CTLR_ISO_TX_BUFFER_SIZE` should be set to 4
  (if timestamps are not used) or 8 (if timestamps are used) above
  :kconfig:option:`CONFIG_BT_CTLR_ISO_TX_SDU_LEN_MAX`. For larger values of
  :kconfig:option:`CONFIG_BT_CTLR_ISO_TX_SDU_LEN_MAX` it may be better to increase
  :kconfig:option:`CONFIG_BT_CTLR_ISO_TX_BUFFERS` instead of
  :kconfig:option:`CONFIG_BT_CTLR_ISO_TX_BUFFER_SIZE`.

Bluetooth Mesh
==============

* The deprecated legacy provisioning OOB API was removed together with the
  ``CONFIG_BT_MESH_PROV_OOB_API_LEGACY`` Kconfig option. The maximum numeric OOB
  authentication size is now always 32 bytes. Applications must replace:

  * ``bt_mesh_input_number()`` with :c:func:`bt_mesh_input_numeric`, which takes the
    numeric value as a little-endian byte array and its size.
  * The ``output_number`` callback of :c:struct:`bt_mesh_prov` with
    :c:member:`bt_mesh_prov.output_numeric`, which receives the numeric value as a
    little-endian byte array and its size.

* The Bluetooth Mesh shell ``sar rx-set`` command now takes its arguments in the order the SAR
  Receiver states are documented and printed: ``<SegThresh> <AckDelayInc> <DiscardTimeout>
  <RxSegIntStep> <AckRetransCount>``. ``AckRetransCount`` moved from the third position to the
  last, so an existing invocation keeps the same number of arguments but assigns them to
  different states. The ``sar rx-get`` and ``sar rx-set`` responses are printed in this new
  order too. Update scripts that call ``sar rx-set`` or parse those responses.

* The Bluetooth Mesh shell ``dfu cli send`` command now takes the transfer mode as ``push`` or
  ``pull`` instead of a number, matching ``blob cli tx``. Replace a numeric mode argument with
  ``push`` or ``pull``.

Networking
**********

* The ``ZFD_IOCTL_POLL_PREPARE``, ``ZFD_IOCTL_POLL_UPDATE``, and
  ``ZFD_IOCTL_POLL_OFFLOAD`` requests have been deprecated. Implement ``poll_prepare``,
  ``poll_update``, and ``poll_offload`` in :c:struct:`fd_op_vtable` instead. Out-of-tree ioctl
  handlers that forward these requests to an in-tree socket should use
  ``zvfs_fdtable_call_poll_prepare()``, ``zvfs_fdtable_call_poll_update()``, and
  ``zvfs_fdtable_call_poll_offload()``, as in-tree sockets no longer handle the ``ZFD_IOCTL_POLL_*``
  requests in their ioctl handlers.

* For ``AF_UNSPEC`` lookups, :c:func:`zsock_getaddrinfo` now returns IPv6 addresses before IPv4
  ones, unless only the IPv4 addresses are reachable, and queries AAAA records before A records.
  Applications that use the first result now connect over IPv6 where they used IPv4. Enable
  :kconfig:option:`CONFIG_NET_SOCKETS_DNS_PREFER_IPV4` to keep IPv4 first, for example with
  offloaded network interfaces, where reachability cannot be determined.

* On an Ethernet interface, :c:func:`zsock_connect`, :c:func:`zsock_sendto` and the other send
  calls now fail with ``ENETUNREACH`` for an IPv4 destination that is neither on the link nor
  reachable through a route or the gateway. Such packets were dropped before, after the send call
  had reported success, and a TCP :c:func:`zsock_connect` failed with ``ETIMEDOUT`` once the
  connect timeout passed. Applications that treat every send error as fatal may need to handle
  ``ENETUNREACH``, for example by trying the next address or waiting for the interface to be
  configured.

* The native network stack runs its timers and deferred work on a dedicated work queue,
  :kconfig:option:`CONFIG_NET_DEDICATED_WORKQUEUE`, which is enabled by default. Code called from
  that work now runs in the ``net_workq`` thread instead of the system work queue: the DNS resolve
  callback of a query that timed out, and network management event callbacks with
  :kconfig:option:`CONFIG_NET_MGMT_EVENT_DIRECT` for the events that work raises. Such code no
  longer runs serialized with the application's own system work queue items, and must not wait for
  work that needs the networking work queue. Applications that increased
  :kconfig:option:`CONFIG_SYSTEM_WORKQUEUE_STACK_SIZE` for the network stack's work should increase
  :kconfig:option:`CONFIG_NET_DEDICATED_WORKQUEUE_STACK_SIZE` instead. Disabling
  :kconfig:option:`CONFIG_NET_DEDICATED_WORKQUEUE` restores the previous behavior and saves the
  thread and its stack.

* Network interface driver APIs are now device API classes. Out-of-tree network drivers must define
  their API instances with :c:macro:`DEVICE_API` and use the renamed structs:

  * ``struct net_if_api`` is now :c:struct:`net_if_driver_api`.
  * ``struct ethernet_api`` is now :c:struct:`ethernet_driver_api`.
  * ``struct dummy_api`` is now :c:struct:`dummy_driver_api`.
  * ``struct ppp_api`` is now :c:struct:`ppp_driver_api`.
  * ``struct canbus_api`` is now :c:struct:`canbus_driver_api`.
  * ``struct offloaded_if_api`` is now :c:struct:`offloaded_if_driver_api`.
  * ``struct virtual_interface_api`` is now :c:struct:`virtual_interface_driver_api`.
  * ``struct hdlc_api`` is now :c:struct:`hdlc_driver_api`.
  * ``struct ieee802154_radio_api`` is now :c:struct:`ieee802154_radio_driver_api`.

  For example, ``static const struct ethernet_api api = {...}`` becomes
  ``static DEVICE_API(ethernet, api) = {...}``. API instances are now always constant, and cannot
  be modified at runtime. (:github:`124334`)

* Wi-Fi drivers must define their API with ``DEVICE_API(wifi_native, name)`` when
  :kconfig:option:`CONFIG_WIFI_USE_NATIVE_NETWORKING` is enabled, or with
  ``DEVICE_API(wifi_offload, name)`` otherwise. ``struct net_wifi_mgmt_offload`` remains available
  to refer to the selected type. (:github:`124334`)

* The default Wi-Fi credentials backend has changed for some targets:

  * Non-secure targets with the TF-M Protected Storage partition now use
    :kconfig:option:`CONFIG_WIFI_CREDENTIALS_BACKEND_PSA_PS` instead of
    :kconfig:option:`CONFIG_WIFI_CREDENTIALS_BACKEND_PSA`.
  * Targets that enable :kconfig:option:`CONFIG_SECURE_STORAGE` now use
    :kconfig:option:`CONFIG_WIFI_CREDENTIALS_BACKEND_PSA_PS` instead of
    :kconfig:option:`CONFIG_WIFI_CREDENTIALS_BACKEND_SETTINGS`.
  * Other non-secure targets with TF-M now use
    :kconfig:option:`CONFIG_WIFI_CREDENTIALS_BACKEND_SETTINGS` instead of
    :kconfig:option:`CONFIG_WIFI_CREDENTIALS_BACKEND_PSA`, which is deprecated.

  The new default backends can't read credentials that the previous backends stored. To keep
  those credentials after updating, enable the previous backend explicitly.

* The extra config files of the samples in :zephyr_file:`samples/net`,
  :zephyr_file:`samples/subsys/mgmt/hawkbit`, :zephyr_file:`samples/subsys/mgmt/updatehub` and
  :zephyr_file:`samples/drivers/modem/hello_hl78xx`, and of the network tests, no longer start with
  ``overlay-`` or ``overlay_``, as that name is reserved for devicetree overlays. Drop the prefix
  from the names passed in ``EXTRA_CONF_FILE``, for example ``-DEXTRA_CONF_FILE=tls.conf`` instead
  of ``-DEXTRA_CONF_FILE=overlay-tls.conf``. These files use new names instead:

  * :zephyr_file:`samples/net/mqtt_publisher/testing.conf` replaces ``overlay-sample.conf``.
  * :zephyr_file:`samples/net/dhcpv6_pd/pd-server.conf` and
    :zephyr_file:`samples/net/dhcpv6_pd/pd-server.overlay` replace ``overlay-server.conf`` and
    ``overlay-server.overlay``.
  * :zephyr_file:`samples/net/ethernet/gptp/multiport.overlay` replaces
    ``overlay-multiport.overlay``.
  * :zephyr_file:`samples/subsys/mgmt/updatehub/local.conf.example` replaces
    ``overlay-prj.conf.example``.

* :c:struct:`ocpp_cs_info` has a new ``auth`` member, which :c:func:`ocpp_init` reads even when
  :kconfig:option:`CONFIG_OCPP_BASIC_AUTH` is disabled. Applications that fill the structure field
  by field must zero-initialize it, or set ``auth.username`` to ``NULL`` to connect without
  authentication. (:github:`125718`)

* :c:macro:`NET_REQUEST_WIFI_CONNECT_STORED` now returns the error from the last connect request
  if it fails for all stored networks, instead of ``0`` (or ``-ENOEXEC`` for static credentials).
  Update applications that call this request to handle this error.

Ethernet
========

* Checksum offload capabilities are now advertised with one bit per IP version and protocol.
  ``ETHERNET_CHECKSUM_SUPPORT_IPV6_HEADER``, ``ETHERNET_CHECKSUM_SUPPORT_TCP`` and
  ``ETHERNET_CHECKSUM_SUPPORT_UDP`` have been removed. :c:enumerator:`NET_IF_CHECKSUM_IPV6_HEADER`
  has been deprecated, as IPv6 has no header checksum and no interface advertises it anymore.
  Drivers reporting ``ETHERNET_CONFIG_TYPE_RX_CHECKSUM_SUPPORT`` or
  ``ETHERNET_CONFIG_TYPE_TX_CHECKSUM_SUPPORT`` must set
  :c:enumerator:`ETHERNET_CHECKSUM_SUPPORT_IPV4_TCP`,
  :c:enumerator:`ETHERNET_CHECKSUM_SUPPORT_IPV4_UDP`,
  :c:enumerator:`ETHERNET_CHECKSUM_SUPPORT_IPV6_TCP` and
  :c:enumerator:`ETHERNET_CHECKSUM_SUPPORT_IPV6_UDP` for the combinations they offload. The old
  bits map per IP version:

  * ``ETHERNET_CHECKSUM_SUPPORT_IPV4_HEADER`` together with ``ETHERNET_CHECKSUM_SUPPORT_TCP`` or
    ``ETHERNET_CHECKSUM_SUPPORT_UDP`` becomes :c:enumerator:`ETHERNET_CHECKSUM_SUPPORT_IPV4_TCP`
    or :c:enumerator:`ETHERNET_CHECKSUM_SUPPORT_IPV4_UDP`.
  * ``ETHERNET_CHECKSUM_SUPPORT_IPV6_HEADER`` together with ``ETHERNET_CHECKSUM_SUPPORT_TCP`` or
    ``ETHERNET_CHECKSUM_SUPPORT_UDP`` becomes :c:enumerator:`ETHERNET_CHECKSUM_SUPPORT_IPV6_TCP`
    or :c:enumerator:`ETHERNET_CHECKSUM_SUPPORT_IPV6_UDP`.

* The HTTP server no longer writes into the application's resource details, so static, static fs
  and websocket resource details can be declared ``const`` and placed in flash. Dynamic resource
  details stay writable, the server keeps the client that holds the resource in them. The
  ``path_len`` member of :c:struct:`http_resource_detail` is deprecated and no longer updated. A
  dynamic GET, DELETE or OPTIONS handler that used it to find the request parameters gets them,
  from the ``?`` on, in the ``data`` of the :c:struct:`http_request_ctx` passed to its first
  callback.

  future release.

* The `zephyr-lang-rust <https://github.com/zephyrproject-rtos/zephyr-lang-rust>`_ module providing
  Rust language support is no longer an optional module of the Zephyr manifest. It is now an
  :ref:`external module <external_module_rust>`; add it to the application manifest to keep using
  Rust. The ``manifest.project-filter +zephyr-lang-rust`` west setting no longer has an effect.

Architectures
*************

* On ARM Cortex-A/R with :kconfig:option:`CONFIG_USE_SWITCH`, ISRs run in SYS mode instead of
  IRQ mode, and nested interrupts and the handlers they call use the per-CPU interrupt stack
  rather than the interrupted thread's stack. Boards and applications that sized
  :kconfig:option:`CONFIG_ISR_STACK_SIZE` for the outermost ISR frame alone may need a larger
  interrupt stack, and code or debuggers that inspect the processor mode inside an ISR see SYS
  mode. (:github:`123041`)

* The portable CPU performance monitoring API has been renamed to disambiguate it from
  power-management units (the ``pmu`` name is used by both). The header
  :file:`include/zephyr/arch/pmu.h` is now :file:`include/zephyr/arch/perf_counter.h`, and its
  ``pmu_*`` functions and types gained a ``perf_counter_`` prefix. (:github:`125939`)
